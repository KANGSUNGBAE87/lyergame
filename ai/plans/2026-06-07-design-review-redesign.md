# 디자인 리뷰 및 재정비안

상태: 구현 전 검토안  
작성일: 2026-06-07  
작성자: codex  
사용한 관점: gstack design-review, gstack plan-design-review, Superpowers brainstorming

## 1. 결론

현재 디자인은 MVP로는 쓸 수 있지만, 새 기획인 "오프라인에서 더 빨리 시작되고, 더 덜 귀찮고, 결과가 더 재밌는 앱"을 충분히 받쳐주지는 못한다.

디자인이 완전히 구린 것은 아니다. 카드, 컬러, 버튼은 기본 완성도가 있고 모바일에서 큰 깨짐도 없다. 하지만 현재 첫 화면은 여전히 설정 화면처럼 보이고, 게임 결과는 점수표 중심이라 상품성 있는 파티게임의 웃음과 반전이 약하다.

판정:

- 현재 디자인 점수: 6.5/10
- 빠른 시작 적합도: 5/10
- 덜 귀찮은 UX 적합도: 6/10
- 결과 재미 적합도: 5.5/10
- 그래픽/브랜드 감성: 6/10
- 구현 전 디자인 재정비 필요 여부: 필요

## 2. 실제 화면 리뷰 근거

브라우저에서 확인한 화면:

- 데스크톱 첫 화면
- 모바일 첫 화면
- 게임 방법 모달
- 카드 확인 화면
- 카드 공개 모달
- 토론 화면
- 현재 투표 화면
- 라이어 지목 화면
- 라운드 결과 화면
- 최종 결과 화면

관찰:

- 모바일 첫 화면에서 `게임 시작` 버튼이 첫 viewport 안에 보이지 않는다.
- 첫 화면에 설정 항목이 길게 이어져 빠른 시작보다 설정 완료가 먼저 느껴진다.
- 가이드 모달은 읽을 수는 있지만 현재 톤이 기능 문서에 가깝다.
- 카드 화면은 시각적으로 괜찮지만, 카드 확인 후 `다음 사람에게 넘기세요` 단계가 없어 오프라인 진행 보조가 약하다.
- 투표 화면은 `+ / -` 입력이라 실제 오프라인 비밀투표 감각과 맞지 않는다.
- 결과 화면은 점수표가 빠르게 나오며, 라이어 공개/정답 공개/웃긴 리캡의 극적 순간이 부족하다.
- 최종 결과 화면은 깔끔하지만 `같은 멤버로 한 판 더`와 리캡이 없어 반복 플레이 유도가 약하다.

## 3. 디자인 목표

새 디자인은 세 가지 감각을 분명히 만들어야 한다.

1. 빠른 시작
   - 앱을 켜면 인원수와 시작 버튼이 바로 보인다.
   - 설정은 뒤로 물러난다.

2. 비밀스러운 패스폰 진행
   - 앱이 다음 사람에게 넘기는 순간을 명확히 안내한다.
   - 카드/투표는 개인 화면이라는 감각을 준다.

3. 크게 터지는 결과
   - 점수표보다 라이어 공개, 정답 공개, 하이라이트가 먼저 나온다.
   - 웃고 놀릴 수 있는 문장을 만든다.

## 4. 추천 디자인 방향

추천 톤: **밝은 파티 미스터리**

이유:

- 지금의 어두운 네온 톤은 미스터리에는 맞지만, 첫 사용자에게 약간 무겁다.
- 완전히 귀여운 톤으로 가면 라이어게임의 긴장감이 약해진다.
- 밝은 포인트 컬러, 큰 카드, 짧은 문장, 가벼운 칭호를 섞으면 한국어 모임/MT/친구 모임에 더 잘 맞는다.

유지할 것:

- 어두운 배경 기반
- 큰 카드
- 강한 포인트 버튼
- 라이어 캐릭터/얼굴 그래픽

바꿀 것:

- 첫 화면 정보 밀도
- 결과 화면의 드라마
- 투표 화면의 방식
- 이름/리캡의 사람 중심 표현

## 5. 화면별 재정비안

### 첫 화면

현재 문제:

- 시작 버튼이 너무 아래에 있다.
- 첫 인상이 "설정 폼"이다.
- 게임 방법 카드가 인원수보다 먼저 와서 빠른 시작을 늦춘다.

개선안:

- 상단: 앱 제목, 짧은 문장, 언어 버튼
- 중앙: 인원수 스테퍼
- 바로 아래: `빠른 시작` 큰 버튼
- 보조: `이름 입력`, `고급 설정`, `게임 방법`

권장 구조:

```text
라이어 게임
한 폰만 돌리면 바로 시작

인원수
-   6명   +
3 4 5 6 8 10 12

[빠른 시작]

[이름 입력]
[고급 설정]
[게임 방법]
```

### 이름 입력

현재 없음.

개선안:

- 접힘 영역 또는 하단 시트 느낌으로 제공한다.
- 기본은 `1번`, `2번` 번호로 시작한다.
- 이름은 선택 입력이다.
- 인원수 변경 시 초과 이름은 숨기고 보존한다.

시각 원칙:

- 입력칸이 첫 화면을 지배하면 안 된다.
- `이름 없이 시작 가능` 문구를 작게 둔다.

### 고급 설정

현재 문제:

- 모든 설정이 첫 화면에 노출되어 부담이 크다.

개선안:

- `고급 설정` 접힘 영역으로 이동한다.
- 닫힌 상태에서는 요약만 보여준다.

예:

```text
고급 설정
라이어 1명 · 3R · 혼합 · 전체 단어팩
```

### 카드 확인

현재 문제:

- 카드는 보기 좋지만, 확인 후 넘김 안내가 약하다.

개선안:

- 카드 확인 전: `민수님, 혼자 확인하세요`
- 카드 확인 중: 제시어/라이어 카드
- 카드 확인 후: `다음 사람에게 넘겨주세요`
- 다음 카드로 넘어갈 때 번호/이름이 명확해야 한다.

### 투표

현재 문제:

- `+ / -` 방식은 투표 기록 입력 UI처럼 느껴진다.
- 비밀투표 감각이 없다.

개선안:

- 패스폰 비밀투표 화면으로 전환한다.
- 현재 투표자 이름을 크게 보여준다.
- 후보 카드를 탭하게 한다.
- 자기 자신은 비활성화한다.
- 선택 후 바로 가림 화면으로 넘어간다.

시각 원칙:

- 후보는 점수표 행이 아니라 카드/버튼으로 보여준다.
- 진행률 `3 / 6명 투표 완료`를 크게 보여준다.

### 동점 화면

현재 없음.

개선안:

- 라이어 포함 여부를 숨긴다.
- `재투표하기`를 기본 CTA로 둔다.
- `빠른 판정`은 보조 CTA로 둔다.

문구:

```text
동점입니다
민수, 지연이 같은 표를 받았습니다.

[재투표하기]
[빠른 판정]
```

### 결과 화면

현재 문제:

- 점수표가 먼저 느껴진다.
- 승패는 보이지만 웃음 포인트가 약하다.

개선안:

- 결과를 단계형으로 보여준다.
- 탭하면 다음 단계로 넘어가게 한다.
- 애니메이션은 짧고 스킵 가능해야 한다.

권장 단계:

1. `이번 라이어는...`
2. `현우!`
3. `정답은 피자였습니다`
4. `라이어가 맞혔습니다` 또는 `시민이 잡았습니다`
5. 하이라이트 칭호
6. 점수표

### 최종 결과

현재 문제:

- 점수표 중심이다.
- 반복 플레이 CTA가 약하다.

개선안:

- 리캡 카드를 먼저 보여준다.
- `같은 멤버로 한 판 더`를 가장 큰 CTA로 둔다.
- `설정 바꾸기`, `기록 보기`는 보조로 둔다.

## 6. 디자인 충돌 검토

확인된 충돌:

- 이름 입력을 크게 노출하면 빠른 시작이 느려진다.
- 결과 연출을 길게 만들면 반복 플레이가 귀찮아진다.
- 투표 내역을 기본 공개하면 비밀투표 감각이 깨진다.
- 밝은 파티 톤을 너무 강하게 쓰면 미스터리 긴장감이 약해진다.

해결:

- 이름 입력은 접힘/선택형.
- 결과 연출은 짧고 스킵 가능.
- 투표 내역은 최종 결과에서만 선택 공개.
- 배경은 어둡게 유지하고 포인트/캐릭터/문구로 파티감을 보강.

## 7. 구현 전 디자인 기준

구현할 때 지켜야 할 기준:

- 모바일 첫 화면에서 `빠른 시작` 버튼은 첫 viewport 안에 보여야 한다.
- 이름 입력은 빠른 시작보다 시각적으로 약해야 한다.
- 고급 설정은 닫힌 상태가 기본이다.
- 카드/투표 단계에는 반드시 `다음 사람에게 넘겨주세요` 계열의 화면이 있어야 한다.
- 결과 화면은 점수표보다 라이어/정답/하이라이트가 먼저 보여야 한다.
- 같은 멤버로 다시 시작하는 버튼은 최종 결과의 가장 큰 CTA여야 한다.

## 8. 최종 판단

바로 기능 구현에 들어가도 동작은 만들 수 있지만, 현재 시각 구조 위에 얹으면 기획의 장점이 약하게 보일 가능성이 크다.

따라서 구현 전에 디자인 방향을 위 기준으로 한 번 재정비하는 것이 맞다.

추천 다음 단계:

1. 이 디자인 재정비안을 승인한다.
2. Superpowers `writing-plans`로 구현 계획을 작성한다.
3. 구현은 `첫 화면/이름/고급 설정`부터 시작한다.
4. 이후 `패스폰 투표/동점 처리`, `결과 연출/리캡` 순서로 진행한다.
