# 오프라인 전용 라이어게임 상품성 평가 리포트

검토일: 2026-06-07  
검토자: codex  
범위: 현재 구현 상태, 오프라인 원폰 앱 포지셔닝, CEO/상품성 리뷰, 디자인 리뷰, QA/구현 리스크 리뷰

## 0. 결론

현재 앱은 "실행 가능한 라이어게임 MVP" 수준은 넘었다. 게임 방법, 12명 지원, 1/3/5라운드, 한국어/영어, 단어팩 분리, 플랫폼 어댑터 준비, 라이어 역전 판정 간소화까지 들어가 있어서 기본 완성도는 있다.

다만 지금 상태 그대로 스토어에 올리면 "또 하나의 라이어게임 앱"으로 보일 가능성이 높다. 상품성을 올리려면 온라인 멀티플레이나 큰 기능 확장보다, 오프라인 원폰 파티 상황에서 더 편하고 더 웃긴 앱으로 포지셔닝하는 것이 좋다.

추천 방향: **"한 폰만 돌리면 바로 시작되는 오프라인 라이어게임 진행자"**.

## 1. 현재 구현 평가

강점:

- 오프라인 원폰 플레이 흐름이 이미 명확하다.
- 설정 화면에서 게임 방법과 옵션 설명을 볼 수 있다.
- 인원수는 3-12명까지 지원하고, 스테퍼와 빠른 선택 버튼으로 조작성이 좋아졌다.
- 라이어 지목 화면에서 단어 선택지를 없애고 시민 판정으로 바꿔 실제 테이블 게임 흐름에 가까워졌다.
- 한국어 기본, 영어 선택, bilingual word pack 구조가 준비되어 있다.
- Toss/Google Play 쪽 로그인, 결제, 광고, 기록을 어댑터 뒤로 둘 수 있는 구조가 있다.

약점:

- 첫 화면 설정 항목이 아직 많아서 초보자는 "그냥 시작"보다 "무엇을 골라야 하지"를 먼저 느낄 수 있다.
- 카테고리 선택은 길게 펼쳐지는 옵션 목록이라, 단어팩/분위기 선택처럼 상품적으로 느껴지지 않는다.
- 라운드 종료 결과가 기능적이라 웃음, 반전, 공유 욕구를 만드는 연출이 약하다.
- 기록 화면은 저장은 되지만 다음 플레이를 유도하는 리캡 또는 하이라이트가 약하다.
- 앱만의 차별화된 이름/모드/팩 전략이 아직 부족하다.

## 2. CEO/상품성 리뷰

상품성 점수: 7/10

지금의 핵심 가치는 "오프라인에서 바로 시작되는 사회자 없는 라이어게임"이다. 이 방향은 충분히 상품성이 있다. 공개 경쟁 사례들도 반복해서 `single phone`, `offline`, `quick rounds`, `many word packs`, `languages`, `premium packs`를 전면에 둔다.

10점 제품이 되려면 다음이 필요하다.

1. 설정 부담을 줄이는 프리셋
   - `처음 하는 사람`, `기본`, `파티`, `고수` 같은 모드를 먼저 보여주고 세부 설정은 접어둔다.
   - 초보자는 설명을 읽지 않아도 "기본으로 시작"을 누르면 된다.

2. 단어팩을 상품처럼 보이게 만들기
   - 현재 카테고리 목록을 `음식/일상`, `학교/회사`, `여행/문화`, `매운맛`, `영어 연습` 같은 팩 단위로 묶는다.
   - 무료 기본팩 + 유료/보상형 확장팩 구조가 자연스럽다.

3. 결과 화면을 웃기게 만들기
   - 단순 점수보다 "이번 라운드 라이어", "가장 많이 의심받은 사람", "역전 성공/실패", "정답 공개"를 크게 보여준다.
   - 오프라인 파티게임은 결과 순간이 곧 바이럴 순간이다.

4. 오프라인을 약점이 아니라 장점으로 말하기
   - 로그인 없음, 와이파이 없음, 한 폰만 필요함, 개인정보 전송 없음.
   - 기록은 로컬 중심으로 두되, 결제 복구/확장팩만 플랫폼 어댑터를 사용한다.

5. 한국어 시장에서의 첫 차별화
   - 영어권 앱과 달리 한국어 술자리/MT/학급/가족/회사 아이스브레이크 상황에 맞춘 단어팩과 말투가 중요하다.
   - "한국어에서 진짜 웃긴 힌트가 나오는 단어팩"이 차별화 포인트가 될 수 있다.

## 3. 디자인/UX 리뷰

디자인 점수: 7/10

최근 수정으로 사용성은 좋아졌다. 특히 언어 선택을 오른쪽 상단 팝오버로 줄인 것, 게임 방법을 모달로 분리한 것, 인원수 조작을 스테퍼로 바꾼 것은 방향이 좋다.

다음 디자인 개선이 우선이다.

- 첫 화면 상단에 `바로 시작` 성격의 기본 모드 버튼을 크게 둔다.
- 세부 설정은 `고급 설정`으로 접어 초보자 화면 밀도를 낮춘다.
- 카테고리는 체크박스 그리드보다 단어팩 카드/칩으로 바꾼다.
- 카드 공개 전에는 "다음 사람에게 넘기세요" 같은 패스폰 프라이버시 화면을 더 명확히 둔다.
- 결과 화면은 점수표보다 라운드 드라마를 먼저 보여준다.
- 히스토리는 단순 기록보다 "지난 판 다시 보기" 또는 "오늘의 MVP"처럼 재시작 욕구를 만들어야 한다.

## 4. QA/구현 리스크 리뷰

검증 결과:

- `npm test` 통과: 13개 테스트 파일, 47개 테스트.
- `npm run build:web` 통과.
- 브라우저 QA 통과:
  - 새 탭에서 현재 앱 실행 시 콘솔 에러 0개.
  - 게임 방법 모달 열림/닫힘 확인.
  - 3명, 1라운드 설정 후 시작 확인.
  - 시작 직후 카드 확인 전 제시어가 DOM에 노출되지 않음 확인.
  - 카드 1장 공개 후 2초 뒤 진행률이 `1 / 3 확인 완료`로 갱신됨 확인.

QA 중 발견해서 즉시 수정한 문제:

- `PeekModal`이 비활성 상태에서도 DOM에 렌더링되어 카드 확인 전 제시어가 접근성/DOM 스냅샷에 잡힐 수 있었다.
- 수정: 비활성 상태에서는 `PeekModal`을 렌더링하지 않게 변경.
- 테스트 추가: `test/peekModal.test.js`.

남은 리스크:

- 실제 모바일 좁은 화면에서 설정 화면 전체 길이와 버튼 밀도 확인이 더 필요하다.
- 영어 단어/문구는 1차 번역 수준이므로 원어민 또는 실제 플레이 QA가 필요하다.
- 로컬 기록은 브라우저/앱 저장소가 지워지면 사라진다. 오프라인 앱이면 괜찮지만 "영구 기록"이라는 표현은 조심해야 한다.
- 결제형 단어팩을 넣을 경우 백엔드 영수증 검증과 복구 플로우가 필수다.
- 플랫폼 어댑터는 좋은 구조지만, MVP에서는 SDK를 붙이기보다 유료팩/복구 요구가 확정된 뒤 구현하는 것이 낫다.

## 5. 다음 작업 우선순위

P0 - 상품성 핵심:

1. 앱 포지셔닝 문장 확정
   - 예: "한 폰만 돌리면 바로 시작되는 오프라인 라이어게임"

2. 시작 프리셋 추가
   - `빠른 시작`, `처음 하는 사람`, `파티`, `고수`
   - 프리셋 선택 후 세부 설정은 고급 영역에 둔다.

3. 단어팩 구조 개편
   - 카테고리 나열에서 팩 선택으로 전환.
   - 무료 기본팩, 한국어 파티팩, 가족/학교/회사팩, 어려운 단어팩으로 나눈다.

4. 결과 화면 강화
   - 라이어 공개, 정답 공개, 역전 여부, 의심 결과를 더 크게 연출한다.
   - 스크린샷으로 남기고 싶은 화면을 목표로 한다.

P1 - 출시 안정성:

1. 모바일 좁은 화면 브라우저 QA.
2. 영어/한국어 카피 QA.
3. 단어팩 중복/난이도 QA.
4. 기록 화면을 세션 리캡으로 개선.

P2 - 수익화:

1. 유료 단어팩 또는 테마팩.
2. 광고 제거 또는 프리미엄 팩.
3. 플랫폼별 결제 어댑터 연결.
4. 백엔드 영수증 검증.

## 6. 하지 않는 것이 좋은 일

- 지금 바로 온라인 멀티플레이를 붙이지 않는다.
- 로그인 기능을 먼저 전면에 내세우지 않는다.
- 결제를 먼저 붙이고 콘텐츠 상품성이 약한 상태로 출시하지 않는다.
- 설정 항목을 계속 늘리지 않는다.
