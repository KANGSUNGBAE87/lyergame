# 빠른 오프라인 플레이 개선 기획안

상태: 검토용 초안  
작성일: 2026-06-07  
작성자: codex  
대상: 라이어게임 V2 상품성 개선

## 1. 목적

이 기획안은 라이어게임을 "오프라인에서 더 빨리 시작되고, 더 덜 귀찮고, 결과가 더 재밌는 앱"으로 개선하기 위한 화면/룰/데이터 설계 초안이다.

핵심 방향:

- 첫 사용자는 인원수만 고르고 10초 안에 시작할 수 있어야 한다.
- 세부 설정은 필요할 때만 열어볼 수 있어야 한다.
- 카드 확인과 투표는 앱이 진행자를 대신해야 한다.
- 결과 화면은 단순 점수표가 아니라 웃음과 반전을 만드는 순간이어야 한다.
- 이름 입력은 재미를 높이는 선택 기능이어야 하며, 빠른 시작을 방해하면 안 된다.

## 2. 구현 대상 요약

이번 기획에서 구현 대상으로 보는 기능은 다음 9개다.

1. 10초 빠른 시작
2. 고급 설정 접기
3. 선택형 플레이어 이름 입력
4. 같은 설정/같은 멤버로 한 판 더
5. 패스폰 카드 확인 안내 강화
6. 패스폰 비밀투표
7. 동점 처리: 재투표 또는 빠른 판정
8. 라이어 공개 연출
9. 라운드 하이라이트와 최종 리캡

## 3. 첫 화면 구조

첫 화면은 설정판이 아니라 시작 화면처럼 보여야 한다.

기본 노출:

- 언어 선택
- 앱 제목과 짧은 설명
- 게임 방법 버튼
- 인원수 선택
- 빠른 시작 버튼
- 플레이어 이름 입력 접힘 영역
- 고급 설정 접힘 영역
- 지난 기록 버튼

빠른 시작 기본값:

- 라이어 1명
- 3라운드
- 혼합 난이도
- 전체 단어팩
- 타이머 없음
- 라이어 카테고리 힌트 ON

고급 설정 안에 넣을 항목:

- 라이어 수
- 난이도
- 라운드 수
- 타이머
- 카테고리/단어팩
- 라이어 카테고리 힌트

## 4. 선택형 플레이어 이름 입력

이름 입력은 추가하는 것이 맞다. 다만 필수가 되면 빠른 시작의 장점을 망치므로 선택 기능으로 둔다.

기본 상태:

- 이름 입력 영역은 접혀 있다.
- 플레이어는 `1번`, `2번`, `3번`처럼 번호로 표시된다.
- `빠른 시작`은 이름 입력 없이 바로 가능하다.

이름 입력을 열었을 때:

- 현재 인원수만큼 입력칸을 보여준다.
- 입력 예: `1번 [민수]`, `2번 [지연]`, `3번 [ ]`.
- 빈칸은 자동으로 번호 표시를 사용한다.
- 일부만 입력해도 시작할 수 있다.
- `전체 지우기`를 제공한다.

인원수 변경 규칙:

- 인원수가 줄면 초과 이름은 화면에서 숨기되 삭제하지 않는다.
- 인원수가 다시 늘면 이전 입력 이름을 복원한다.
- 같은 설정으로 다시 시작할 때 이름도 함께 유지한다.

표시 규칙:

- 이름이 있으면 `민수`를 우선 표시한다.
- 이름이 없으면 `1번`을 표시한다.
- 이름과 번호가 함께 필요할 때는 `민수(1번)` 형식을 사용한다.

## 5. 같은 설정/같은 멤버로 한 판 더

최종 결과 화면의 기본 CTA는 `같은 멤버로 한 판 더`가 되어야 한다.

동작:

- 직전 게임의 설정을 유지한다.
- 플레이어 이름도 유지한다.
- 점수, 라운드 기록, 투표 기록은 새 게임으로 초기화한다.
- 단어와 라이어는 새로 뽑는다.

보조 버튼:

- `설정 바꾸기`: 첫 화면으로 돌아간다.
- `기록 보기`: 지난 기록 화면으로 이동한다.

## 6. 패스폰 카드 확인

카드 확인은 앱이 진행자를 대신하는 흐름이어야 한다.

권장 흐름:

1. `민수님, 카드를 확인하세요`
2. 플레이어가 카드 버튼을 누른다.
3. 2초 동안 시민은 제시어, 라이어는 라이어 표시를 본다.
4. 화면이 가려지며 `다음 사람에게 넘겨주세요`를 보여준다.
5. 다음 플레이어 카드 확인으로 이어진다.

주의:

- 카드 확인 전에는 제시어가 DOM/화면에 노출되지 않아야 한다.
- 확인 후 다음 플레이어에게 넘기는 화면이 명확해야 한다.
- 이름이 없는 플레이어는 `1번 플레이어`처럼 표시한다.

## 7. 패스폰 비밀투표

현재의 `+ / -` 표 수 입력은 오프라인 분위기와 맞지 않는다. 투표도 휴대폰을 한 바퀴 돌리는 비밀투표로 바꾼다.

권장 흐름:

1. 토론 화면에서 `투표 시작`을 누른다.
2. `민수님, 라이어라고 생각하는 사람을 고르세요`를 표시한다.
3. 후보 카드를 보여준다.
4. 자기 자신은 선택할 수 없다.
5. 선택 후 바로 가림 화면을 보여준다.
6. `투표 완료. 다음 사람에게 넘겨주세요`를 표시한다.
7. 마지막 플레이어까지 반복한다.

기본 공개 범위:

- 라운드 중에는 누가 누구를 찍었는지 보여주지 않는다.
- 라운드 결과에는 득표 수와 최다 득표자만 보여준다.
- 최종 결과에서 `투표 내역 보기`를 누른 경우에만 `민수 -> 지연` 같은 상세 내역을 선택적으로 보여줄 수 있다.

저장 데이터:

- `votesByVoter`: 각 플레이어가 누구에게 투표했는지
- `voteCounts`: 각 플레이어가 몇 표를 받았는지
- `votedOutIndices`: 최종 지목된 플레이어 목록
- `runoffOf`: 결선투표가 있었을 때 원래 동점 후보 목록

## 8. 동점 처리

동점이 발생했을 때 앱은 내부적으로 라이어 포함 여부를 판단할 수 있지만, 사용자에게 먼저 알려주면 안 된다. 라이어 포함 여부를 먼저 알려주면 재투표가 힌트를 받은 투표가 되기 때문이다.

1차 투표 동점 화면:

```text
동점입니다
민수, 지연이 같은 표를 받았습니다.
동점 후보만 다시 투표할까요?

[재투표하기]
[빠른 판정]
```

선택지:

- `재투표하기`: 동점 후보만 놓고 다시 패스폰 비밀투표를 진행한다.
- `빠른 판정`: 현재 동점 후보를 그대로 지목 대상으로 처리한다.

빠른 판정 규칙:

- 동점 후보 안에 라이어가 있으면 라이어 지목 성공으로 처리한다.
- 동점 후보 안에 라이어가 없으면 시민 지목 실패, 라이어 승리로 처리한다.

재투표 규칙:

- 후보는 1차 동점 후보로 제한한다.
- 재투표에서도 단독 최다 득표자가 나오면 그 플레이어를 최종 지목자로 처리한다.
- 재투표에서도 동점이면 자동으로 `빠른 판정`을 적용한다.

## 9. 라이어 공개 연출

결과 화면은 바로 점수표로 가지 않는다. 먼저 라이어 공개와 정답 공개를 크게 보여준다.

권장 단계:

1. `이번 라이어는...`
2. `현우!`
3. `정답은 피자였습니다`
4. `라이어가 맞혔습니다` 또는 `라이어가 틀렸습니다`
5. `라이어 승리` 또는 `시민 승리`
6. 점수표
7. 다음 라운드 또는 최종 결과 버튼

동점/투표 결과가 있는 경우:

- `민수와 지연이 동점이었습니다`
- `재투표 끝에 현우가 지목됐습니다`
- `빠른 판정으로 동점 후보를 함께 확인했습니다`

## 10. 라운드 하이라이트

라운드 결과에는 짧은 칭호를 붙인다. 칭호는 놀림거리이면서도 개인을 지나치게 공격하지 않는 톤이어야 한다.

가능한 하이라이트:

- `최다 의심`: 해당 라운드에서 가장 많은 표를 받은 플레이어
- `억울한 시민`: 라이어가 아닌데 최다 득표자가 된 플레이어
- `완벽히 숨은 라이어`: 라이어가 0표 또는 낮은 표로 지목되지 않고 승리한 경우
- `역전 라이어`: 지목됐지만 제시어를 맞혀 승리한 라이어
- `시민 대혼란`: 최다 득표자가 모두 시민이었던 경우

기본 공개 원칙:

- 누가 누구를 찍었는지는 공개하지 않는다.
- 표의 패턴과 결과만 공개한다.

## 11. 최종 결과 리캡

최종 결과 화면은 점수표보다 리캡을 먼저 보여준다.

추천 리캡:

- `오늘의 우승자`: 최종 점수 1등
- `오늘의 의심왕`: 전체 라운드에서 가장 많은 표를 받은 플레이어
- `가장 억울한 시민`: 시민인데 가장 많이 지목된 플레이어
- `최고의 라이어`: 라이어로 가장 많이 승리한 플레이어
- `역전의 주인공`: 역전에 성공한 라이어

선택 기능:

- `투표 내역 보기`: 최종 결과에서만 제공한다.
- 기본은 닫혀 있어야 한다.
- 열면 라운드별로 `민수 -> 지연` 형태의 투표 내역을 보여준다.

## 12. 충돌 검토

확인된 충돌:

- 이름 입력을 필수로 만들면 `10초 빠른 시작`과 충돌한다.
- 투표자 상세 공개를 기본으로 하면 `비밀투표`와 충돌한다.
- 동점 후보 안에 라이어가 있는지 먼저 알려주면 `재투표 공정성`과 충돌한다.
- 동점 때 무한 재투표를 허용하면 `덜 귀찮은 앱` 방향과 충돌한다.

해결 방식:

- 이름 입력은 선택형으로 둔다.
- 투표자 상세 공개는 최종 결과의 선택 버튼으로 둔다.
- 동점 화면에서는 라이어 포함 여부를 숨긴다.
- 재투표는 1회만 허용하고, 또 동점이면 빠른 판정을 적용한다.

## 14. 검토할 질문

구현 전에 사용자가 검토하면 좋은 항목은 다음이다.

1. 이름 표시 형식은 `민수`만 쓸지, `민수(1번)`을 기본으로 할지.
2. 재투표에서도 동점이면 자동 빠른 판정으로 확정할지.
3. 최종 결과에서 `투표 내역 보기`를 제공할지.
4. 라운드 하이라이트 톤을 귀엽게 할지, 미스터리하게 할지.

현재 추천값:

- 이름 표시: 게임 중에는 `민수`, 필요한 곳에서만 `민수(1번)`.
- 재투표 동점: 자동 빠른 판정.
- 투표 내역: 최종 결과에서 선택 공개.
- 하이라이트 톤: 가볍고 놀리기 좋은 파티 톤.
